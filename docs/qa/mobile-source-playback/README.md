# Native source playback

Signed-in web, desktop and Android players can use the existing yt-dlp/FFmpeg path when the service is configured, activated and the client supports its media formats. Guests retain the embedded YouTube provider. Song lookup, selected YouTube IDs, queue entries and history remain unchanged. Device size or user-agent strings do not authorize extraction.

The availability endpoint validates the current account. Create, poll and renew retain account/session-version receipts, rate and byte limits, origin checks and expiry validation. Cancellation releases owned jobs. `GET /api/media/resolve` returns `enabled` and a coarse reason: `service_unconfigured`, `service_disabled`, `authentication_required` or `service_unavailable`. Replies are private and noncacheable, without credentials or provider diagnostics. Eligibility alone does not prove successful extraction.

Clients supporting both Opus/WebM and AAC/MP4 request `auto`. The worker respects yt-dlp's upstream quality ranking and falls back to a compatible codec for that same video. Clients supporting one format request that format explicitly. FFmpeg copies compressed audio packets without re-encoding. The quality indicator reports the prepared codec, bitrate (marked `~` when estimated), sample rate and channel count; no 320 kbps or lossless quality is invented.

Run `node docs/qa/mobile-source-playback/check.cjs` for actual route and receipt checks using isolated account/provider adapters. It covers guest denial and authenticated availability for web, Electron, Android and iOS, plus account/session ownership, cancellation, origin/rate limits and the disabled-service gate. `browser.cjs` exercises real decoding, minimized playback, pause and cleanup in three browser engines with offline synthetic audio. See [audio fidelity checks](../audio-quality/README.md) for measured DSP and packet preservation.

Production activation remains separate. Keep `MEDIA_SERVICE_PLAYBACK_ENABLED=0` until extraction, private delivery and decoding pass from the deployed worker. The existing YouTube embed remains the fallback. Offline tests and desktop browser emulation cannot establish phone lock-screen behavior or live provider access; current hosted evidence is in [Vercel results](../vercel-media/RESULTS.md).
